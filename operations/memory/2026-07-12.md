### Key Architecture Decisions
- Engine-agnostic core: zero dependency on sqlvec-db / graphvec-db
- Provider pattern over DI container: typed InterfaceToken<T> + priority-based ProviderRegistry
- Interface-first design: stable contracts first, implementations as separate adapters
- IHealthOrchestrator follows K8s probe model (liveness/readiness/startup)
- HealthOrchestrator caches startup result; liveness probes are synchronous (<10ms expectation)
- MetricsRegistry uses key-based dedup ((name + canonical labels) → same instance)
- All error types from core/types.ts — every interface includes error states
- Every interface includes observability hooks and capacity/state inspection methods
